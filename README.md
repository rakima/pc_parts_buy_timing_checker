# 時期判定官 ヴィクトル

PCパーツの商品ページから現在価格を取得し、SQLiteに蓄積した過去価格と比較して「今が買い時か」を判定するデスクトップツールです。価格を調査するたびに、判定結果に応じた時期判定官ヴィクトルの表情とセリフが表示されます。

## 主な機能

- ツクモの商品目録から監視対象を選択して登録
- 取得済み商品候補の商品名検索、URL重複登録の防止
- GPU、CPU、SSD、メモリの商品目録と次ページ追加取得
- 登録時の在庫・出荷状態の保存と表示
- 容量・規格など主要スペックの抽出、保存、表示
- ユーザー操作による価格調査（常時監視は行いません）
- SQLiteへの取得価格と取得日時の保存
- 直近30日平均との比較による買い時判定
- 日次最安値・日次平均、7日・30日移動平均、短期トレンド
- 指示待ち・調査中・判定結果に応じたヴィクトル画像とセリフ
- 19世紀ヨーロッパの貴族の書斎をモチーフにしたアンティークUI
- 商品ごとの価格履歴一覧
- 日次平均と最安値の価格推移グラフ
- 価格調査時の在庫・詳細スペック更新と在庫履歴
- 履歴の期間・表示切替とCSV保存
- メーカー型番・JANコードによる別店舗の同一商品候補と価格比較
- 自前履歴が不足する初回調査での価格.com市場最安値履歴による参考判定
- 価格.com対応付け・キャッシュ・最終連携状態の確認と修正
- カテゴリ別の監視商品目録と商品候補の列ソート
- 取得失敗を含む操作ログのローテーション保存
- ワーカースレッドによる非同期取得
- ヴィクトルの調査中表示を最低3秒保つ吟味演出

## 必要環境

- Python 3.11以降（`tkinter`を含むPython環境）
- インターネット接続

画像を高品質に縮小表示するため、Pillowを使用します。

```powershell
python -m pip install -r requirements.txt
```

## 起動方法

```powershell
python main.py
```

初回起動時に `data/victor.db`、`config/settings.json`、`logs/victor.log` が自動作成されます。

## 商品登録と価格調査

1. `商品を探す` を押します。
2. 店舗と、`GPU`、`CPU`、`SSD`、`メモリ`のいずれかを選択します。
3. `商品一覧を取得`を押します。
4. 必要に応じて検索欄へ`RTX 5070`などの商品名を入力します。
5. 商品を選択し、`監視対象に追加`を押します。
6. メイン画面の一覧から商品を選択し、`価格を調査する`を押します。
7. 調査完了後、現在価格、30日平均、平均との差、最安値、判定を確認します。

通常操作で商品URLを入力する必要はありません。商品詳細URLは選択した候補から内部的に保存され、以降の価格調査に使用されます。同じURLの商品が登録済みの場合は既存商品を案内し、重複登録しません。

監視対象への追加成功は操作を遮るダイアログを出さず、メイン画面の状態欄へ静かに表示します。価格調査は取得がすぐ完了した場合も、ヴィクトルの調査・吟味中表示を開始から最低3秒間保ってから結果を表示します。

商品一覧の検索は取得済み候補に対するローカル部分一致です。検索文字を変更してもサイトへ再アクセスしません。同じ店舗・カテゴリの先頭ページは5分間メモリへキャッシュします。
商品候補の`現在価格`、`主な仕様`、`メーカー`の見出しを押すと、その列で昇順・降順に並べ替えられます。メイン画面の監視商品目録はカテゴリごとにまとめて表示します。
さらに候補を表示する場合は`次ページを取得`を押します。ページは1回の操作につき1ページだけ追加し、取得済みURLは重複表示しません。在庫・出荷表示と詳細スペックは価格調査時にも商品詳細ページから更新され、在庫状態は履歴として保存されます。商品検索画面の`別店舗と比較`では、他店舗の先頭3ページを手動取得し、JANコードまたはメーカー型番が一致する商品を優先して価格順に表示します。商品名だけの一致は誤認防止のため`候補`と表示します。

商品目録の構造化説明と商品名から、可能な範囲で主要スペックを抽出します。価格調査時は商品詳細ページの仕様表で置き換えます。GPUは型番とVRAM、CPUは型番・ソケット・クーラー、SSDは容量・形状・接続規格、メモリは容量・DDR世代・速度・CLを表示します。

## 判定ロジック

今回の取得価格を含めず、直近30日以内の日次平均と比較します。同日に複数回取得しても、その日の平均を1日分として扱うため調査回数の偏りを受けません。最低3日分、かつ最古と最新の履歴が7日以上離れていない場合は「データ不足」と表示します。

7日平均は最新履歴日を含む直近7日の日次平均です。短期トレンドは7日平均と、それ以前の30日範囲の日次平均を比較し、差が+2%超なら`上昇`、-2%未満なら`下落`、それ以外は`横ばい`と表示します。履歴画面には直近30日の日次平均線と日次最安値、日別の取得回数を表示します。

日次平均の極端な外れ値はMAD方式で除外し、有効日数と期間から判定信頼度を表示します。在庫なし・販売終了の商品には買い時判定を出しません。履歴画面では7日・30日・全期間、日次・取得履歴・在庫履歴を切り替え、現在の表をCSV保存できます。

判定信頼度には履歴期間と件数に加えて価格変動率を反映します。価格変動が大きい場合は信頼度を下げ、設定ファイル内の判定閾値が矛盾している場合は起動時にエラーとして検出します。

自前の店舗価格履歴が判定条件を満たさない場合に限り、商品型番から価格.comの商品を特定し、直近30日の日別最安価格を参考に初回判定します。価格.comの履歴はツクモやドスパラ単体の価格ではなく、掲載ショップ群における市場最安値です。判定画面の`参考データ`で、自前履歴と価格.com市場履歴を区別できます。自前履歴が十分に蓄積された後は自前履歴を優先します。

価格.comの商品マッピングと履歴はDBへ保存し、24時間以内はキャッシュを利用します。商品検索画面や検索欄の操作ではアクセスせず、自前履歴が不足した商品の手動価格調査時だけ取得します。メイン画面の`価格.com連携`では、対応URL、照合方法、キャッシュ件数、最終取得、連携状態を確認し、誤った対応付けの解除または正しい商品URLの手動設定ができます。タイムアウト、リトライ回数、リトライ間隔、キャッシュ時間、外部履歴の最低件数、外部履歴の保持日数は`config/settings.json`で変更できます。保持期間を過ぎた外部履歴は起動時に削除します。

| 平均との差 | 判定 |
| --- | --- |
| +5%以上 | 時期が悪い |
| -5%より高く+5%未満 | 微妙 |
| -10%より高く-5%以下 | 悪くない |
| -15%より高く-10%以下 | 買い時 |
| -15%以下 | 絶好の買い時 |

期間、必要履歴数、各境界値は `config/settings.json` で変更できます。

## 対応サイトと注意事項

| 取得サイト | 対応状況 | URL |
| --- | --- | --- |
| ツクモ | GPU・CPU・SSD・メモリ一覧、次ページ、商品詳細の税込ネット価格 | URLは画面での入力不要 |
| ドスパラ | GPU・CPU・SSD・メモリ一覧、次ページ、商品詳細の価格・在庫・仕様 | URLは画面での入力不要 |
| ソフマップ | GPU・CPU・SSD・メモリ一覧、次ページ、商品詳細の価格・仕様 | URLは画面での入力不要 |

2026年8月14日にソフマップのGPU・CPU・SSD・メモリ先頭ページから各24件を取得し、GPU先頭商品の詳細価格と仕様を確認しました。価格取得アダプターはJPYの`product:price:amount`を優先し、見つからない場合はJSON-LDへフォールバックします。

Amazon、パソコン工房などのサイト専用アダプターは未実装です。ログイン、JavaScript実行、CAPTCHA、アクセス制限が必要なページは取得できません。

サイトの利用規約を確認して利用してください。HTML構造の変更により商品目録や価格を取得できなくなる場合があります。本ツールはユーザーが一覧取得または価格調査を実行したときだけアクセスし、常時監視や自動巡回は行いません。商品目録は5分キャッシュし、短時間の再取得を抑えます。一部商品を解析できない場合はその商品だけをログへ記録して残りを表示します。取得失敗はアプリ全体を停止させず、`logs/victor.log` に記録します。

**本ツールの買い時判定は価格履歴を元にした参考情報であり、将来の価格を保証するものではありません。** 購入判断は送料、在庫、販売元、保証なども確認した上で行ってください。

店舗横断比較は取得できた識別子に基づく候補表示です。JANコードまたはメーカー型番がない商品は正確に同一判定できないため、商品名と仕様を購入前に確認してください。通信障害、タイムアウト、販売終了、HTML解析変更はログとエラー表示で区別します。

価格.com連携も外部サイトのHTML構造変更により利用できなくなる可能性があります。取得や厳格な商品照合に失敗した場合は誤った履歴を採用せず、通常のデータ不足判定へ戻ります。

## データ保存先

- 商品・価格履歴: `data/victor.db`
- 設定: `config/settings.json`
- ログ: `logs/victor.log`
- キャラクター画像: `assets/images/`

画像が存在しない、または読み込めない場合はテキストのプレースホルダーを表示します。
判定後は「時期が悪い」の暗赤から「絶好の買い時」のゴールドまで、結果に応じて判定欄・セリフ・パネル枠のアクセント色が変わります。
